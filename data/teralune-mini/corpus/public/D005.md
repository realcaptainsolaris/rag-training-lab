# Migrating from Orbit 2.4 to 3.0

## Contract changes

Orbit 3.0 was released on 2026-02-10. Change the API prefix from /api/v2 to /api/v3. The webhook retry window changes from 24 to 72 hours. The access-token lifetime changes from 120 to 60 minutes. Historical contracts remain correct for their own generation.

Plan these changes independently. Moving the HTTP prefix does not update a receiver database retention task. Rotating service credentials does not change the sender generation. During a staged deployment, log the generation alongside delivery identifiers so an incident can be reconstructed without guessing which contract applied.

## Retention and traffic

New workspaces change from a default of 30 days to 90 days. Existing workspace retention is not changed automatically by an upgrade. The workspace request budget changes from 500 to 1000 requests per minute. Traffic from multiple keys in the same workspace shares that budget.

Before cutover, inventory time-based assumptions in cleanup jobs and dashboards. Check receivers, authentication caches, export clients and retention configuration separately. A larger default for new workspaces cannot recover measurements already removed under an older policy.

## Cutover record

Export the existing configuration and record the current retention value before changing the deployment. Test against an isolated workspace, inspect one read, one write and one callback, then schedule the production cutover. If the deployment is rolled back, restore the client prefix deliberately rather than allowing individual clients to choose one automatically.

A customer note saying callbacks last one day describes the old contract. Resolve such a note against the deployed generation and the official contract. The publication date alone does not establish which rule applies.
