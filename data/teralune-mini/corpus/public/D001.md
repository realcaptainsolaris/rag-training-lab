# Orbit 3 Getting Started

## Create a workspace

Teralune Orbit groups device identities and incoming observations inside a workspace. A device belongs to one workspace; creating a team does not move a device. Choose a stable workspace slug before connecting an integration. The examples use ws-amber-lab in the organisation org-amber. A workspace is an isolation boundary, not a folder label. A credential issued for one workspace cannot read another workspace simply by changing a query parameter.

Begin with a dedicated test workspace. Register two devices with distinct external identifiers and confirm that their clocks use UTC. A display name is editable, whereas an external identifier is used to reconcile incoming data. Reusing the same external identifier for two physical devices makes downstream diagnosis difficult. Keep a local inventory that records which device owns each identifier.

## Send the first observation

Use /api/v3/measurements to submit observations. Send timestamps as RFC 3339 strings with an explicit UTC offset. The ingestion response confirms acceptance, not delivery to every downstream consumer. A webhook can arrive after a successful ingestion response.

```http
POST /api/v3/measurements
Authorization: Bearer <TRAINING_TOKEN>
Content-Type: application/json

{"device_id":"dev-lab-17","timestamp":"2026-03-10T12:00:00Z","value":21.6,"unit":"degC"}
```

Use a measurement name together with the unit; do not infer temperature from a field called value. Preserve the response identifier in your integration log so support can distinguish a missing submission from a delayed notification. Never paste a bearer credential into a ticket.

## Read back and disconnect

A fresh workspace uses a default retention of 90 days. Read back the observation with the same workspace credential before configuring alerts or exports. If no rows appear, compare the workspace, device identifier and timestamp first. Expanding the time range cannot repair a request made against the wrong workspace.

When removing the test integration, revoke its credential and stop its sender. Deleting a dashboard does not revoke an API key. Keep device registration separate from credential management so that removing a reader does not accidentally remove the device history.
