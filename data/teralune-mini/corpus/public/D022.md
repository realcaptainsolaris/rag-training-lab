# Pagination and cursors

## Cursor traversal

The default page size is 100 and the maximum is 500. The response field next_cursor supplies the next request value for cursor. Treat it as opaque: parsing or editing its contents is unsupported. Continue until no next cursor is returned.

Keep filters unchanged while traversing a result. A cursor is not a bookmark that can be moved to a different query. A consumer that changes the device filter between requests can silently splice two different result sets into one local file. Store the initial request alongside the continuation state.

### Cursor validity

A cursor expires after 15 minutes and is bound to workspace, filters and sort order. An expired cursor requires a new traversal. Do not repeatedly retry the same expired value while the local process waits for a downstream file writer.

For a slow consumer, buffer a page durably before fetching the next one. If the local checkpoint is lost, restart from an explicit time interval and reconcile identifiers. A cursor lifetime is separate from the OAuth token lifetime: renewing a token does not renew a cursor.

### Ordering and consistency

Measurements are ordered by timestamp ascending, then measurement_id ascending. This traversal is not a frozen snapshot. New observations can arrive while a reader is paging through the selected interval. For a stable analytical extract, create an export job instead of treating a cursor chain as a transactionally fixed view.

The parent query establishes the workspace, interval and sort order. Each page continues that query; the page alone does not carry all of the assumptions needed to reproduce the result. Keep the complete parent request when recording a page failure, rather than forwarding only the opaque cursor.

## Recover an interrupted traversal

A traversal checkpoint includes the initial query and the last durably accepted page. If the process crashes after writing the page but before saving its continuation value, the next run may see the same records again. The local sink should recognize records already committed. Otherwise a cautious restart can create duplicate output even though the server never returned a record twice within one traversal.

If a cursor has expired, establish a new interval and reconcile by measurement identity. Do not construct a continuation token from the last displayed timestamp. Several measurements can share that timestamp, and the stable ordering includes the measurement identifier as well. Restarting only after the timestamp can skip siblings; restarting inclusively without reconciliation can duplicate them.

A progress display should distinguish pages received from records committed. A page downloaded into memory but lost on a crash is not durable progress. Similarly, a local file writer that has not flushed its output should not advance a source checkpoint that cannot be replayed safely.

## Query ownership and child pages

The parent query establishes which workspace, interval and filters the traversal represents. Child pages provide a continuation of that query and are meaningful only within that contract. An isolated page copied to a support ticket may show valid measurements without showing which filter excluded a missing device. Preserve the parent request separately from the page body.

For parallel readers, assign each reader an explicit nonoverlapping work interval or reconcile overlaps. Sharing one mutable cursor variable across independent readers creates ownership problems: one reader can advance it while another still writes an older page. A cursor is a continuation value, not a distributed work queue.

When a user reports that the second page looks different from the first, compare the effective query, request order and server result, not just the table rendering. A browser can retain an old filter in its state even after the operator edits the visible time range. Record the actual outgoing request used by each page.
