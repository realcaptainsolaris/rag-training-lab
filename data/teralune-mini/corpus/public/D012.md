# Asynchronous Data Export

## Create a job

Submit a job to /api/v3/exports with scope exports:create. Supported output formats are CSV, JSONL. One export may span at most 7 days and contain at most 1000000 rows. Larger requests must be split into independently tracked jobs. Splitting by date does not bypass a row limit within one period.

The service returns a job identifier before a file exists. Preserve that identifier and poll its state, or subscribe to the completion event. Retrying a successful job submission because the file is not immediately available can create additional jobs. Keep job creation separate from download retries.

## Completion and download

The event export.completed signals that the file is ready. A download link expires after 24 hours. The link lifetime is independent of the webhook retry deadline. A late callback can therefore refer to a link that is no longer usable. Request a new export after verifying the original job and its selected interval; do not assume a callback failure means the file never existed.

CSV is convenient for a flat analysis table; JSONL preserves one structured record per line. A completed export is a snapshot of the selected data, not a live subscription. Deleting the local downloaded file does not change server retention. Treat the download URL as sensitive while it is active and avoid including it in public tickets.
